# 长会话与恢复能力评估

这组修改基于设备上的改进建议，继续使用标准库和 httpx，不引入常驻服务、分词器或额外依赖。

| 建议 | 实施与取舍 |
|---|---|
| 上下文保护 | `max_context_chars` 默认 500000，可全局或按 API 配置覆盖。统计消息与工具 schema 的 JSON 字符；80% 请求前提醒，超限停止发送并保留历史。识别结构化上下文超限错误，提示 `/compact`。字符预算不能推断模型 token 窗口。 |
| WAL | 使用 WAL、FULL 同步和 5000ms busy timeout。数据库及 WAL/SHM 文件权限 0600。WAL 改善读写并行，仍只有一个写入者，revision 冲突保护继续生效。 |
| 即时保存 | 用户输入、助手回复、工具执行前和每个工具结果后保存检查点；未完成的工具在保存副本中标记结果未知。流式文本和思考另存草稿，首次片段及之后最多每 2 秒保存，单字段最多保留最后 64000 字符。 |
| 检索 | `/recall TEXT` 按需扫描已保存标题、正文和工具参数，支持中文及字面子串，最多返回 20 个会话。静默写入正文仍隐藏。当前规模先采用扫描，避免 FTS 索引构建、同步与额外明文副本。 |
| 空回答 | JSON/SSE 共用结构化空回答异常，不自动重试已接受的响应；保留服务端 usage 和已完成的思考消息。区分明确的 length 结束与仅有思考，不把所有空回答都推断为 token 耗尽。`/stats` 增加 reasoning_tokens。 |
| 导出与管理 | `/export [ID] [markdown\|json] [PATH]` 导出完整保存记录和恢复草稿，仅创建新的 0600 文件。Markdown 按消息分段；JSON 保留元数据。补充备份、草稿、WAL 和导出文件的明文位置说明。 |

`/compact [N]` 默认保留最近 6 个用户轮次，连同完整的工具调用/结果、思考回传和当前系统指令，在新会话中继续。完整原会话继续保存；提示中注明原会话 ID。这是无需模型调用的显式上下文缩减，不生成模型摘要，也不在请求失败后自动丢弃历史。过大的单一轮次仍可能需要更小的 N、新会话或按行读取文件。

自动到期删除暂未加入。保留策略、历史诊断备份及归档文件的清理应由用户明确选择；本次不会删除现有会话或诊断文件。

需要修正原建议中的两点判断：DELETE journal 同样提供事务恢复；WAL 不是消除 revision 冲突的手段，分阶段保存也不以 WAL 为逻辑前提。WAL + NORMAL 在断电/硬重启后可能回滚最近提交，因此保留 FULL。参考 [SQLite WAL 文档](https://sqlite.org/wal.html)。设备验收应记录实际 SQLite 版本，并使用已修复 WAL-reset 问题的版本。

恢复边界：已执行工具与结果落盘之间无法保证外部副作用“恰好一次”；未知结果需先检查实际状态。草稿最多丢失最近约 2 秒尚未保存的片段，恢复时不自动作为完整回答或工具调用提交给模型。
